# Multiplier photo matching

## Reader and decision

A Multiplier developer uploads a store photograph, inspects which physical product the model identified, and decides whether the evidence is sufficient or another check is needed. The platform also demonstrates the manufacturer dataset and the export needed for independent scoring.

The result must answer the identification question before showing its filename, pipeline or cost. A photograph can support a family without establishing an accessory package or regional variant. Confidence describes the visible evidence and must not be presented as measured accuracy.

## Structure

Use the existing upload, comparison, catalogue and history flows. On a completed run, put the selected product or unresolved outcome first, with qualitative confidence beside it. Give the photograph and manufacturer reference the main working area. Put visible supporting evidence next, with missing evidence and retake guidance where present. Retain object selection for multi-product scenes. Keep cost, latency and technical details in the existing expandable run record. Preserve exports and the actual-control spotlight tour.

On upload, one primary action adds a store photo. Manufacturer reference images show what it will be compared with. Catalogue records reveal their original documents and the written details used for matching. The guide states the assumed manufacturer/store dataset and separate answer labels. History lists actual runs without inventing an accuracy aggregate.

## Evidence and states

The first read gives the outcome and confidence. The second read compares the visible product and manufacturer image. The third read opens evidence, catalogue details and export metadata. Use actual API fields only. A failed or uncertain run stays failed or uncertain; it must not be presented as a successful classification. Loading, saved, failed and completed states each show the next available action. Do not change model prompts, gates or confidence thresholds in this design pass.

This adapts SHVA so-what-dashboard's decision, evidence and record-panel guidance to a photo workflow. There is no chart data requiring a chart, ranking, large-number row or invented surprise. Do not add those to satisfy a dashboard template. The reader can inspect reference views, missing evidence and an expected-model verification; no threshold slider may change the frozen matching policy.

## Appearance and interaction

Retain the current Clinical Signal Minimal reference, now revised through the owner's wiki taste: white and cool-grey ground, dark text, restrained green action, generous space, hairline borders and real product photography. Give the product decision larger type than filenames and costs. No eyebrows, stock slogans or decorative metric cards. Existing shared controls and source APIs remain in use.

Use the same cue for each action. Keep secondary material behind a clear control. The spotlight tour explains the real catalogue, document, upload, result and export controls with Next, Back, Skip and Escape. Never start a paid run during the tour. Motion is limited to state changes and respects reduced-motion settings.
