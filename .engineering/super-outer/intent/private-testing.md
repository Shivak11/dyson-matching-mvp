# Private Dyson photo testing

Version 1, 16 October 2026. Governing implementation plan: docs/PLAN-private-testing-app.md. Shared API: docs/private-testing-api.md. Preserve the prior app's working comparison layout and manufacturer catalogue.

The owner uploads fresh store photographs, chooses Identify or explicitly claims a model for Verify, and watches real stages while inference runs in the background. Each physical machine has its own selectable box and match/not sure/not in catalogue decision, qualitative confidence, supporting/missing evidence and retake guidance. A completed prediction can be downloaded unchanged in JSON and CSV. Latency, model/provider/configuration and cost are available in Run details without secrets or server paths.

The main content is the store photograph beside the manufacturer reference. Existing neutral surfaces, dark text, blue actions, spacing, keyboard focus and responsive stacking remain the design system. Export controls appear only when a saved envelope is available. Technical fields stay within an accessible expandable section. Identify and Verify controls state the difference before the paid Run action. Errors preserve files and describe the next available action. Progress reports real stages without a fabricated percentage.

Historical evaluation and reporting are excluded from this testing interface and source bundle; private labels/scoring are never admitted. No matching prompt, catalogue, threshold, gate, image processing or model/provider setting is tuned during this UI conversion. No new accuracy claims or paid calls. A design prototype uses clearly identified development fixtures and is excluded from runtime packaging.

Deliver locally unless an officially supported owner-private Sites architecture can run the real workflow. No tunnels, public data, hosted credential changes or additional services are authorised. No architecture-explainer Site in this task. Owner acceptance remains pending.
